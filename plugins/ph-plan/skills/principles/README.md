# Principles

Leaf skills: `user-invocable: false`. The model reads them; they never appear in
your slash menu. Read the leaf in full before applying it, and name which
principle changed which decision.

These are the **interactive** half of the pair. `ph-build` carries its own set
for unattended work, and several are direct inversions — that is deliberate, not
an inconsistency. The harness decides which one is correct.

| Principle | Inverse in `ph-build` |
| --- | --- |
| `block-on-the-human` | `never-block-on-the-human` |
| `walk-the-tree` | — |
| `close-or-block-the-dimension` | — |
| `write-it-down` | — |
| `name-the-destination` | `outcome-oriented-execution` (related) |
| `one-way-doors-first` | shares the one-way-door test with the cost gate |

Descriptions live in the [plugin README](../../README.md) — one place, so they
cannot drift.
